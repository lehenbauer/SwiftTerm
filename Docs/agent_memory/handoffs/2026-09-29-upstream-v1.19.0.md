# SwiftTerm upstream v1.19.0 integration — 2026-09-29

Status: candidate `85cb8ca` is frozen and qualified on functional gates, but
is **on hold for performance** and is **not merged**. `main` stays at
`2747875`. Nothing was pushed, and Whisp was not durably re-pinned. No
shipping performance fix was found.

Disposition: retain the qualified integration branch and hold adoption. The release costs are not accepted by this qualification pass; a separate decision or semantics-preserving optimization is required before main integration.

- Adopt Miguel de Icaza's **released** SwiftTerm v1.19.0 atop the Whisp fork,

  IO/SIMD changes, is excluded. The release's Ghostty terminfo alignment does
  not bring the claimed throughput improvement with it.

- `3d7656e` — clear-history keeps absolute row identities, translates
  surviving selections and drops trimmed ones, and invalidates the view's
  search snapshot. Captured history is parsed in a scratch terminal; its
  OSC 133 marks, group identities and cell tags are deliberately not imported.
  Witness: 6 new cases red on `f17a40f` (14 issues), green after.
- `bb0f736` — blink changes go through one appearance-row invalidator
  (line cache, Metal row generation, and the actual CG viewport band, also

- `60e144a` — themes compose with Metal transparency and reverse screen: the
  native background setter owns the clear host layer and Metal opacity; UIKit
  updates the saved normal background when the theme changes while reversed.

  explicit ANSI colors are untouched. Themes own their full RGBA background,

- `169a538` + `85cb8ca` — three more clear-history defects: keep the

## Whisp companion: OSC 133 mirror override (mandatory)

- Root cause: tmux's grid is authoritative for Whisp mirrors. OSC 133 arrives
  in the live stream, but captured history carries only text and rendition.
  v1.19's built-in A/N/L handling can insert a fresh line and arm prompt-click
  input, so the mirror diverges from tmux and from snapshot replay.
- `77b1d871` adds `Terminal.ignoreSemanticPromptsForTmuxMirror()`
  (`ios/Whisp/TerminalMirrorPromptSemantics.swift`) and calls it from the
  AppKit, shared UIKit and support-guest factories. It registers an empty
  OSC 133 handler via existing public API that precedes built-in dispatch,
  and it persists across reset. Standalone SwiftTerm keeps upstream semantics.
  On the old pin it is a no-op.
- Witness: helper source linked into a SwiftTerm probe matches saved fork-tmux
  fixtures for live input, hydration and five reset cases; a control without
  it reproduces the mismatch. 4 probe tests pass against `85cb8ca`. Whisp
  transport hops were source-traced; no Whisp app or service was launched.
- **Any re-pin to v1.19-based SwiftTerm must include `77b1d871` or an
  equivalent.** Unadapted Whisp reproduces the grid divergence.

## Performance (why the candidate is on hold)

Headless feed benchmark (package-benchmark 1.36.2, release, same lock and
compiler; forward and reverse orders; compiler-overlapped runs discarded;
10,000 samples per case):

- Release vs old base `cf7764f`: about 6–8% slower at p50. The cost appears
  in upstream's initial OSC 133 integration and its next revision; later
  combining/buffer and hyperlink changes are within noise.
- Frozen `85cb8ca` vs `2747875`: +10.3% / +9.3% p50, cleanly separated.
  `85cb8ca` ≈ `60e144a`; the later corrections add no resolved cost.
- Ablations (diagnostic only; all break OSC 133 behavior and cannot ship):
  no cell tags is neutral; removing six semantic row create/recycle operations
  removes 67–78% of the `60e144a` gap. Same-session split vs `85cb8ca`:
  dropping the attach-time weak-self load plus weak-owner store is −2.6% /
  −4.1% p50 (separated); semantic destroy and clone-metadata copy are
  unresolved. The owner store is required for OSC 133 cross-buffer behavior.
  Deltas from different sessions are not additive.
- These are feed-throughput numbers, not measured typing latency.
RenderBench (native, main-thread feed ticks):

- Most scenarios are within 0.2–2.3%; CG dense overlaps and is faster.
- Metal `arabic-line` feed ticks/s drop about 39% (already −38% at `f17a40f`;
  later commits add nothing resolvable). The original frozen CG comparison is at parity; the separate instrumented comparison is about 2% lower, with only one retained M run.
- This is **not a 40% rendering slowdown.** Diagnostic accounting (B =
  `2747875`, M = `f17a40f`): per-tick Arabic feed cost rises +24% through the
  view (+23% CG) and +34% in a short headless control with identical grid
  witnesses. Metal successful `buildDrawData` calls rise from 41.0/s to
  53.7/s while ms per build falls 16.39 → 14.21, because B skipped 13.7
  draws/s on a busy frame semaphore and M 0.2/s. Draw calls/s are flat.
  Builds are not presented frames; presentation and command-buffer
  completion were not measured, and why B's semaphore was busier is not
  established. The accounting is an identity over measured totals, not a
  causal split.
- CG accounting rests on one retained M run (the third position failed its
  focus gate on the initial attempt and both retries).
- The prior 3–4% BiDi acceptance (2026-08-08) does not cover these costs.
