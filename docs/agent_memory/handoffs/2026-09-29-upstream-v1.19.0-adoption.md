## Adoption decision and what it accepts

- Accepted: the measured headless ASCII feed cost, **+9.3% / +10.3% p50** vs
  `2747875` (mostly OSC 133 semantic row bookkeeping). It is **accepted, not
  fixed**; no semantics-preserving reduction was shipped.
- CG RenderBench workloads are near baseline. The Metal `arabic-line` tick drop
  and the long Arabic feed cost (upstream-inherent) are not adoption
  priorities: Whisp runs with Metal disabled and Arabic-heavy output is not a
  Whisp priority. The measurements stand as recorded in the appendix.
- Unchanged: the functional qualification, limitations (no human visual or
  physical-keyboard acceptance, Metal evidence is draw data), and the mandatory
  Whisp OSC 133 override.

Upstream performance work studied at upstream `a2706d2` (all absent from
v1.19.0, v1.20.0 lacks `6ea9082`; source-only study, no Whisp measurement):

- `6ea9082` "Avoid expensive Swift side tables when using 'weak'" directly
  targets the measured owner overhead (the weak-self/weak-owner split was
  −2.6%/−4.1% p50 of the gap). First candidate to measure when it ships.
- Engine-side, automatic for any `Terminal.feed` caller: `b018f39`/`4b6cfc6`
  SIMD/Span byte scans (ASCII-heavy), `a786c9d` SGR colon bitmask, `768c4f0`
  interned-attribute cache, `fe3f9e5` packed cells, `1cd513a` line-ring
  rotation. Author percentages are not measured for Whisp; treat any gain as
  additive to, not a replacement for, the accepted cost until measured with
  `Benchmarks/`.
- `82fe50d` Ghostty PTY reader changes only `LocalProcess`/`TerminalIOPipeline`.
  Whisp uses its own WebSocket transport and never `LocalProcess`, so it gets
  **zero** benefit. The broader background-parse + CG snapshot architecture
  (`d06bf29`, `38d688f`, `222400c`, `282a7bd`, `59b3017`, `970eeb4`) is
  applicable only after it ships in a release, and is a real re-port against
  fork CG repaint-skip and caret ownership, not a clean merge.

Threading trap:

- v1.19's feed doc comments mention a "(possibly background) feed thread",
  but v1.19 lacks the terminal lock infrastructure (`222400c`), delegate
  callback marshalling (`282a7bd`) and snapshot CG rendering (`59b3017`).
  **Do not move Whisp's `feed` off main on v1.19.**
- Whisp already receives, buffers, coalesces and applies backpressure off main
  (nonisolated receive loop + `ObservedPaneBufferStore` actor). What remains on
  main around the feed is the erase-scrollback scan, widget-marker filtering,
  grid pinning and replay bookkeeping. Moving the pure scans off main can be
  prepared later but needs profiling first, and per-address parser state must
  reset exactly on connection/resync-epoch change.
- Ordering to preserve in any threading change: replay bytes and following
  live bytes as one ordered stream; the epoch/connection fence as the last
  check before feed; grid pin before feed; OSC/DA replies are emitted
  synchronously during parse into the send path.

Upstream 2.0 migration notes:

- 2.0 removes `getTerminal()`/direct parser access; the `nonisolated`
  `TerminalFeedSender` is the usable feed entry. Preserve across migration:
  the OSC 133 mirror override (`77b1d871`), grid pinning/replay/resync epoch
  semantics, selection translation, CG row cache and caret ownership, and all
  fork contracts listed in `current_state.md` and `decisions.md`.
